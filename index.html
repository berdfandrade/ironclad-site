Como funciona Arquitetura Garantias Roadmap Leituras GitHub
RUST · LSM-TREE · RAFT

Um banco chave-valor que não perde dados quando um nó cai.

Ironclad é um distributed embedded key-value store escrito em Rust: armazenamento persistente com WAL próprio, replicação por consenso Raft e recuperação de falhas testada de propósito.

Começar Ver a arquitetura

$ ironclad-cli set user:123 '{"name":"Bernardo"}'

{"name":"Bernardo"}
$ ironclad-cli del user:123
OK
O CAMINHO DE UMA ESCRITA

Um SET parece simples. Por baixo, são sete passos.

Tudo com concorrência e sem corromper dados — inclusive se a máquina cair no meio.

  1. 01RecebeA requisição chega pelo protocolo TCP binário, com cada tamanho validado.
  2. 02ValidaO Command Engine valida a chave e serializa o comando.
  3. 03RegistraO líder grava a entrada no log do Raft, com checksum CRC32.
  4. 04ReplicaOs seguidores recebem a entrada, gravam em disco e confirmam.
  5. 05CommitCom a maioria gravada em disco, a entrada está confirmada.
  6. 06AplicaWAL e MemTable são atualizados num único lote atômico.
  7. 07RespondeO cliente recebe OK — e o dado sobrevive a um crash.
ARQUITETURA

Cinco camadas, cada uma com uma responsabilidade.

O núcleo — storage engine e consenso — é implementado à mão. Bibliotecas entram só como apoio: Tokio, Bytes, Tracing.

A DEMONSTRAÇÃO

Derrube o líder. Os dados continuam lá.

  1. Subir cinco nós.
  2. Escrever milhares de registros.
  3. Derrubar o líder abruptamente.
  4. Observar a eleição de um novo líder.
  5. Reconectar o nó antigo.
  6. Verificar que todos convergiram para o mesmo estado.

E tudo isso provado com testes automatizados, não com um print.
